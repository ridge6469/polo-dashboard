# polo-dashboard

Polo 后台账号用量看板。网页放在 GitHub Pages，数据在你自己的服务器上，登录后才能读取。

- 看板地址：https://ridge6469.github.io/polo-dashboard/
- 网页代码：`docs/`（纯静态 HTML/JS；统计看板的图表库 ECharts 放在 `docs/vendor/`，没有其他第三方依赖）

## 数据从哪来

```
GitHub Pages 网页 ──HTTPS + 用户登录──▶ 服务器网关（用户、邀请码、权限）──▶ 本机只读接口 ──▶ 定时采集的快照
```

- 服务器约每 3 分钟用无头浏览器读取一次 Polo 后台（含每个账号详情里的重置时间、今日统计），生成快照；实时数字（并发、RPM、5h / 7d %、今日累计）每 30 秒读一次。采集全在你自己的服务器上跑，GitHub 只放网页文件，网页取数据直接连服务器，不占 GitHub 的额度。
- 网页只读取快照，不会触发后台刷新，也没有任何修改后台的功能。
- 网关只接受来自 `https://ridge6469.github.io` 的跨域请求；登录失败过多会被暂时拒绝。

## 用量看板

- **总池并发走势**（全部已登录成员）：看板顶部或侧栏进入，按北京时间选日期，查看每 5 分钟的采样平均、峰值和近七天对照。记录的是 Polo 顶部的总池在飞数，不是自己账号的并发之和；没有采样不会画成零。

- **实时**（只有管理员看得到）：看板最上面一行是自身实时并发、总池实时并发、号池可用账号、自身 RPM（含总池 RPM）。服务器每 30 秒从 Polo 读一次，页面每 15 秒取一次、原地更新；每个号前面圆圈里的并发和 RPM / TPM、已绑定会话、5h / 7d 的 % 也按这个数字显示（成员只看得到自己号的）。手机列表和卡片视图里，并发显示成醒目的“并发 N”标签（大于 0 时为蓝色渐变）。Polo 的浏览器在做结算查询时会暂停读取，这时显示最近一次的快照并注明。
- **冷却原因**：Polo 卡片上的橙色提示（如 “Anthropic 7d subscription limit rejected (util=1.0) · 10时20分”）会读成“7d 额度已满 · 10小时20分后恢复”：那个窗口按 util 显示（util=1.0 就是 100%，红色），恢复时间按 Polo 显示的剩余时间算（精确到分钟）。Polo 自己的 7d 条在被拒后常显示 0%，以这条提示为准；“周额度用完”筛选、按 7d 排序、高用量统计都算上它。鼠标停在提示上可以看 Polo 的原文。
- **用满保持**：服务器一旦知道某个号的 5h / 7d 满了（Polo 的冷却原因写明这个窗口被拒，或者用量到 100%），就记下恢复时间，到点前一直显示用满（100%、“X 额度已满 · …后恢复”），Polo 的提示消失或用量没数据也不变；这期间也不让 Polo 页面去刷新这个号的用量。到了恢复时间自动解除（Anthropic 提前重置时也会提前解除）。鼠标停在提示上可以看记下的时间和来源。
- **并发、上下文和缓存 / 官方额度怎么算**（「额度窗口」页“缓存和额度”卡片下半部分）：Polo 每次刷新用量 % 且 % 变了就记一“步”，记下这一步的平均 / 最高并发、每个请求带的 token（≈ 上下文大小）、缓存占比、花了多少钱。上半看“并发高 / 上下文大 → 缓存低？→ 每 1% 额度跑的钱少？”（相关系数、三者一起的拟合、分组表）；下半反推官方额度的算法：把每一步的钱拆成输入输出、缓存写、缓存读，算每类 1 美元消耗的额度是平均的几倍（超过 1 倍说明这类在额度里比它的 API 价“贵”），还有各号自己的“每 1% 额度 ≈ 多少美元”；数据够了再拆出输入和输出、换算成“1 个输出 / 缓存写 / 缓存读 token ≈ 几个输入 token”。缓存写有 5 分钟和 1 小时两种价（Opus 5.5：5 / 8 美元每百万；Fable 5.2：10 / 16），Polo 不按号给各占多少：“缓存读 vs 其余”不受影响；拆缓存写、拆输入输出的数按“全是 5 分钟”和“全是 1 小时”各算一遍，显示成范围。各号额度大小不同，并发 / 缓存和“每 1% 额度跑的钱”的关系都是同一个号自己比（换成“是这个号平均的几倍”）。Polo 只给自己号池的缓存读写合计，所以只用一个号占号池花费 ≥ 80% 的步；要几百步（几天）才看得准。从 2026-11-23 18:45 开始记录。
- **额度窗口**：每个号 5H / 7D 条下面一行是“`$777` 已跑 · 满 ≈$810”：前一个是这个号**当前这个 5h / 7d 额度窗口里已经跑了多少额度**（所有模型合计，和结算用同一个数：Polo 的成本，按请求跑完的时刻记、和 Anthropic 的用量 % 同步，只增不减，每 30 秒更新），后一个是**用满预测**：这个窗口跑到 100% 大约是多少钱（Polo 每次把用量 % 刷新到新的数，就用那一刻的“已跑 ÷ %”算；用量不到 5% 时用以往窗口的中位数，灰色显示；已打满的显示“打满时 $…”，就是用量到 100% 那一刻的已跑。打满时还在跑的长请求跑完会再记账，所以已跑可能比打满时多，鼠标停在上面能看到多了多少）。「用量统计」按请求开始的时刻记、跑完才写，长请求会晚到十几二十分钟，只用来补开始记卡片计数之前的部分和输入输出 token（结束 45 分钟后再查一遍补上晚到的）。列表里的“7D / 30D”来自 Polo 抽屉，比“今日”计数更新得慢，少于今日时按今日显示。两行布局，放不下会自动换行，手机上字体调大也不会压在一起。点金额进入「额度窗口」页：列出每个号当前的 5h / 7d 窗口（已跑、满 ≈、还能跑 ≈）和最近结束的窗口；选一个号可以看它**每一个**窗口（起止、已跑额度、请求、Token、其中 Opus / Fable、用量 %、用满预测、缓存占比、是否打满）和变化图。**缓存和额度**：用量 % 每涨 3 点（5h）/ 2 点（7d）记一段，记下这段花了多少钱、缓存占比多少（缓存 token ÷ 全部 token；卡片上的 token 含缓存，「用量统计」的只有输入 + 输出），用散点图、拟合和分组汇总看“缓存占比高低对每 1% 额度能跑多少钱”的影响（至少 8 段才给结论）。窗口起止按 Polo 显示的“X 后重置”推算（重置前 1 天内精确到分钟）；窗口结束 10 分钟后按起止时间精确查一次。成员只看得到自己的号。窗口从 2026-11-23 14:20 开始记录，用满预测和缓存从 15:58 开始。
- 列表 / 卡片两种显示方式；默认按 **5h 用量从小到大**（剩余额度多的在前，一样时再按 7d、名称），也可按 7d 用量、重置时间、今日费用、最近使用、名称、出口 IP 排序，旁边的按钮切换从小到大 / 从大到小（没有数据的始终排最后）。
- **按归属筛选**（管理员）：账号列表上方一排按钮「全选 / 我 / 各成员」，后面是号数。全选时点某一项 = 只看它；再点别的是加选、再点一次取消（可多选）；选齐了就回到全选。选择会记住。
- “显示周额度用完的”：取消勾选就隐藏 7d 窗口已到 100% 的号，标题旁会写隐藏了几个。
- 列表里每个号的“状态 / 实时”：圆圈里是此刻正在发的请求数（并发）；“会话”是此刻活跃的会话；“已绑定会话”是 Polo 固定分给这个号、还没释放的对话数（同一段对话一直走同一个号），不是正在用的数量，跟额度和结算无关。点这一小块会弹出说明。
- 显示方式、排序、归属筛选、是否显示周额度用完的都会记住（存在本机浏览器里）。
- **手机版**（宽度 ≤ 760px，按小米 15 Pro 约 412 CSS 像素宽调过）：底部导航栏（管理员：看板 / 统计 / 结算 / 用户 / 更多；成员：看板 / 已归档 / 收益 / 设置），表格改成带标签的两列卡片，弹窗从底部弹出、按钮加大，结算页标签横向滑动，说明文字默认收起；适配全面屏的安全区域。
- **手机滚动性能**：手机和触屏设备上不用毛玻璃模糊（改成接近不透明的纯色背景）、阴影收小、不要全屏网格和入场动画，图表最多按 2 倍像素画；正在滑动时自动刷新会等停下来再重绘。电脑上保持毛玻璃。

## 用户与权限

- **注册**：凭管理员生成的邀请码注册；邀请码可设置可用次数、有效期、是否需要审批、默认可见账号。
- **普通用户**：只能看到管理员分配的账号。
- **管理员**：可以看全部数据，审批 / 停用 / 删除用户，重置密码，分配可见账号，管理邀请码，查看登录记录，增加其他管理员。
- 登录有效期 12 小时；停用、重置密码后，对方的登录立即失效。

## 结算（按成员）

- **怎么结**：“结算 → 待结算”里每位成员一张卡片。点谁的“结算”，就向 Polo“用量统计”精确查询他名下每个号从上次结算点到点击时间前 2 分钟的额度（北京时间，精确到秒），算出应付多少人民币；确认后自动写入结算点，下次从下一秒接着算。一天可以结算多次。
- **归属时段**：每个号按时间段归属，每段有自己的结算点。换成员时选新成员从哪一秒开始算（现在 / 加入 Polo 时 / 自定义），旧成员到前一秒为止，各自结算——同一秒只算给一个人。起点不能早于已经结算到的时间。未归属的号算管理员自己的。用量看板的账号上有归属标签：“我”= 管理员自己的号，归属给成员的显示成员备注名（只有管理员看得到；以前这里的 default 是 Polo 的分组，不是归属）。
- **计算**：毛收入 = （额度 + 调整）（美元）× 汇率（默认 1.5）。先用毛收入回收成员名下号的成本，回本部分全归成员、不分成；超出成本的部分再按管理员抽成（默认 30%，每个成员可单独设置）分。人民币四舍五入到分。
- **USDT**：结算或标记付款时可选 USDT，USDT = 应付人民币 ÷ 汇率。汇率可选欧易 C2C / 币安 P2P / CoinGecko / 外汇（服务器每 10 分钟取一次），也可以手动填；结算单记下所用汇率、来源和时间。
- **成本（回本）**：按成员合并计算。新加入 Polo 的号归给成员时自动记成本：开号日记一次，之后每月同一天续费再记一次（号归档后停止），金额按席位：高级 834 元、标准 167 元（可在设置里改）。已有的号默认不计，可手动“记成本”。每笔成本可以改金额或免除。每张结算单记下成本合计、之前已回本、本次回本（不分成）、参与分成、还差多少。
- **撤销**：只能撤销某位成员最近一张（已付款的要先取消付款），结算点和回本进度一起退回。
- **上家结算**（“结算 → 上家结算”）：上家按整个号池（所有成员的号 + 我的号）的总额度给我结算。收到钱后“添加结算点”：输入这次结算的额度、或累计额度、或时间，系统向 Polo 查出这个额度是哪一秒达到的（按天 → 小时 → 分钟 → 秒，约 1 分钟），结算点记在那一秒，不是录入时间。记账额度写上家给的数（例如 5087.11），Polo 实际额度另记（例如跨过目标的那一条请求让它变成 5087.1966），多出来的部分“结转”到下一段待结算，下次按额度找时间时先抵掉；按时间结算时记账 = Polo 实际 + 结转。结算点首尾相接；每段记下总额度、我的号、各成员的号（按当时的归属时段拆分）和收款（可选）。已结算和待结算都按号列出，每段显示各成员是否已给结清。给成员结算时可以选“结算到上家结算点”。只能撤销最近一个结算点；第一个结算点之前可以改起点（默认 2026-11-20 00:00，Polo 在这之前没有数据）。
- **统计看板**（管理员）：任选日期范围（今天 / 本周 / 本月 / 上月……），看每个号每天的额度、产出（按汇率）、我的利润（估）、成员应得（估）、请求和 Token、模型分布、24 小时分布，以及期间的结算和成本。可以切换统计范围：全部（号池）/ 仅我的号 / 仅成员号 / 某位成员。利润按当天的归属和抽成比例估算（未扣成员回本），实际以结算单为准。图表用 [Apache ECharts](https://echarts.apache.org/) 6.1.0（`docs/vendor/`，Apache-2.0，只在打开统计看板时加载）。
- **备注昵称**：管理员在“用户管理”里给用户加备注，管理页面里优先显示备注；成员自己看不到。
- **成员**的“我的收益”：管理员没开“显示计算明细”时只有一行待结算金额；开了的是图表版：概览卡片（本期待结算、累计已结算 / 已付 / 未付、累计贡献额度、回本进度或结算单价）、每个号一张卡片（贡献额度、你的收入、成本、净收益、收入覆盖成本的进度）、各号贡献占比环形图、各号收入和成本柱形图、每天贡献的额度（按号堆叠，只算号归他的时段）、本期怎么算（一步步）、成本与回本进度条、每次结算给他的钱（已付 / 未付），以及成本记录、结算记录、各单账号明细。按固定单价结算的成员不显示成本、回本和毛收入。内容和金额由服务器算好写好，页面只管画（结算规则不在公开的前端代码里）。

## 忘记管理员密码

SSH 登录服务器后运行：

```bash
polo-dashboard-admin reset-password admin   # 打印临时密码，登录后需修改
polo-dashboard-admin list-users
```

本仓库是公开的。以下内容一律不要提交：

- 账号用量快照、导出的 CSV/JSON 数据
- Cookie、浏览器配置目录、`.env` 等本地凭据文件
